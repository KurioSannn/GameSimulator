# 20 STORY AND CASE ENGINE SPECIFICATION

## Purpose

Turn the 100+ real-world case library into an interactive, branching, state-aware story system.

## Case classes

### 1. Major historical case

A real event adapted into a major decision point.

### 2. Recurring systemic case

A problem that can reappear because a structural condition remains unresolved.

### 3. Secondary consequence

A downstream issue caused by previous decisions.

### 4. Regional case

A problem primarily affecting one or several regions.

### 5. National case

A problem whose impact crosses many regions or the entire country.

## Case lifecycle

```text
eligible
→ triggered
→ briefing
→ decision
→ implementation
→ immediate effect
→ delayed effect queue
→ regional effects
→ national effects
→ stakeholder response
→ sentiment update
→ follow-up eligibility
→ resolved/recurring
```

## Trigger types

- date/time
- region condition
- resource threshold
- trend threshold
- disaster risk
- policy prerequisite
- previous case outcome
- stakeholder state
- sentiment state
- randomized eligible event

## Decision structure

Each major case should usually have at least 3 meaningful approaches when evidence permits.

Avoid fake choices that are mechanically identical.

## Consequence structure

Each choice should support, where relevant:

- immediate effects
- delayed effects
- direct regional effects
- spillover effects
- national effects
- stakeholder effects
- fiscal effects
- environmental effects
- sentiment effects
- future case effects

## Causal graph requirement

A case record should identify what it can affect and what can affect it.

## Historical fidelity rule

Facts must remain factual. Alternative decisions and outcomes are explicitly simulated.

## News wrapper

A game briefing can be written in original Bahasa Indonesia, based on the documented facts, without copying source articles.

## Story pacing

A five-year run should begin with simpler cases and gradually expose multi-variable crises.
